## [Qwen3.8 27B 在 Artificial Analysis 评测中得分 52，超越更大模型](https://artificialanalysis.ai/models/qwen3-8-27b) ⭐️ 8.0/10

阿里巴巴 Qwen 团队发布了 Qwen3.8-27B，这是一款原生的多模态稠密开源权重模型；该模型在 Artificial Analysis 上的得分为 52，高于 Qwen3.6 27B 的 38 分，并与 DeepSeek V4 Flash 0731 持平，超越了许多更大规模的模型。 这一结果挑战了前沿智能需要数千亿参数规模的假设——27B 稠密模型在游戏电脑上就能运行，却能匹敌更大的专有模型，有望降低算力成本并让先进 AI 在本地可用。 Qwen3.8-27B 是 27B 参数的稠密模型（非混合专家），原生多模态，针对编程、智能体工作流和办公自动化进行了优化；其 Artificial Analysis 得分 52 使其超过了中型模型（40B–150B）的得分区间，并追平了大型模型 DeepSeek V4 Flash 0731。

hackernews · anana_ · 8月17日 17:25 · [社区讨论](https://news.ycombinator.com/item?id=49334544)

**背景**: Qwen 是阿里巴巴的开源权重大语言模型系列。Artificial Analysis 是一个独立平台，从质量、价格、速度和延迟等维度对 AI 模型进行基准测试，并以智力指数（Intelligence Index）汇总成单一分数。稠密 27B 参数模型对每个 token 都会激活全部参数，不同于仅激活子集的混合专家模型，这使其在本地推理中更可预测。上一代 Qwen3.6 27B 在同一 Artificial Analysis 评分体系下得分为 38，因此提升到 52 很显著。

## [AI 生成的 Copilot Autofix 工作流使 Snowflake Jira 遭到入侵](https://www.wiz.io/blog/red-agent-snowflake-copilot-cicd-bug) ⭐️ 7.0/10

Wiz 的安全研究人员报告称，由 GitHub Copilot Autofix 生成的 GitHub Actions 工作流存在模板注入漏洞，可能使攻击者入侵 Snowflake 的 Jira 实例。问题源于在 shell 命令中不安全地展开了 GitHub 事件数据。 这一事件凸显出 AI 生成的代码可能大规模引入安全漏洞，需要严格的审查和静态分析。随着 Copilot 等工具加速代码变更，企业必须将安全重心从代码生成转向验证，以防止真实世界的入侵。 存在漏洞的工作流使用了通过模板展开进行的脚本注入，其中来自 GitHub issue 字段的不可信输入被插入到 shell 命令中。社区成员指出，像 zizmor 这样的静态分析工具可以检测此类问题，但也有人质疑直接将问题归因于 Copilot，因为该 PR 中由 Copilot 共同编写的提交与漏洞代码无关。

hackernews · galnagli · 8月17日 14:18 · [社区讨论](https://news.ycombinator.com/item?id=49331423)

**背景**: GitHub Copilot Autofix 是一项 AI 功能，可为代码扫描警报建议修复方案，由开发人员审核后应用。GitHub Actions 允许使用 YAML 配置自动化 CI/CD 工作流。Snowflake 是一家云数据平台公司，而 Jira 是广泛使用的问题跟踪工具，其中的内部工单可能包含敏感信息。
